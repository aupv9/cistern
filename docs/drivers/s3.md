# S3 driver (`s3`)

Copies the objects under a bucket and prefix of any S3-compatible service, incrementally by ETag,
and restores them into the same or another bucket and prefix.

This driver backs up a **source** bucket. To store backups in S3, use an
[S3 repository](../repositories.md) — the two are independent and can be combined.

## Parameters

| Parameter | Default | Description |
| --- | --- | --- |
| `endpoint` | — | Required. `https://host[:port]` |
| `bucket` | — | Required. Source bucket |
| `prefix` | `""` | Only objects whose key starts with this prefix |
| `region` | `us-east-1` | Signing region |
| `path_style` | `false` | Path-style addressing (MinIO) |
| `access_key_id`, `secret_access_key`, `session_token` | `AWS_*` variables | Credentials (read-only access is enough for backups) |
| `ca_file`, `insecure_skip_verify` | — | TLS options |
| `part_size_mb` | `16` | Part size when uploading objects during restore |
| `full` | `false` | Always copy every object |
| `restore_bucket` | source bucket | Target bucket for restores |
| `restore_prefix` | — | Replace the source prefix with this prefix on restore (for example `restored/`) |
| `only` | — | Restore only keys starting with this string |
| `overwrite` | `false` | Allow restoring over existing objects |

## How incremental backups work

Each object is stored as its own artifact, `objects/<sha256 of key>`, so a single object can be
restored without reading the others. `index.json` lists every object with its key, size, ETag,
Content-Type, artifact and the snapshot that holds its data.

On the next backup, an object whose ETag and size are unchanged is not copied again. Its index entry
points directly at the snapshot that holds the data, and that snapshot is added to the new
snapshot's `depends_on`:

```
backup 1 (full)          backup 2                  backup 3 (nothing changed)
a.txt  v1  ─ stored      a.txt  v2  ─ stored        a.txt   → backup 2
big.bin    ─ stored      big.bin    → backup 1      big.bin → backup 1
                         depends_on: [1]            depends_on: [1, 2]
```

Because entries point at the snapshot holding the data rather than at the previous snapshot,
dependency chains do not grow over time. Retention never removes a snapshot that a kept snapshot
depends on.

Reading the previous index requires the private key (`encryption.identity_file`). Without it, or
when the endpoint, bucket or prefix changed, or with `full: true`, the driver copies everything. The
manifest records what happened in `source.extra`: `objects`, `copied`, `reused`, `copied_bytes` and
`mode` (`full (…reason…)` or `incremental from <snapshot>`).

Objects are downloaded with `If-Match: <ETag>`. An object that changes between listing and download
fails the backup with `object "…" changed during backup; run the job again` instead of producing a
mixed copy.

## Restore

```sh
cistern restore --job uploads --set restore_prefix=restored/ --yes        # next to the original
cistern restore --job uploads --snapshot 20261101 --set restore_prefix=v1/ --yes
cistern restore --job uploads --set only=uploads/2026/ --set overwrite=true --yes
```

Before writing anything, the driver lists the target and refuses to continue if any object would be
overwritten, unless `overwrite=true`. Objects are written with their original Content-Type.

## Limitations

- Only object content and Content-Type are kept; user metadata (`x-amz-meta-*`), tags, ACLs and
  object versions are not.
- Objects are copied one at a time; buckets with very many small objects back up slowly.
- Every object is one artifact in the repository, each with its own age header.

## Manual recovery

`index.json` maps keys to artifacts. An entry with an empty `snapshot` is stored in the same
snapshot; otherwise in the snapshot it names:

```sh
age -d -i identity.txt artifacts/index.json.gz.age | gunzip > index.json
# for each entry: artifact objects/ab/cd… of snapshot S → key K
age -d -i identity.txt ../S/artifacts/objects/ab/cd….gz.age | gunzip | aws s3 cp - "s3://bucket/K"
```
